# Parking Lot – Database Design

We will use a traditional relational database design (PostgreSQL), keeping active and historical parking tickets in the
same table.

## 1. parking_lot

Stores parking facility information.

| Column | Type         | Constraint |
|--------|--------------|------------|
| id     | UUID         | PK         |
| name   | VARCHAR(100) | NOT NULL   |
| active | BOOLEAN      | NOT NULL   |

## 2. parking_floor

Stores floors belonging to a parking lot.

| Column         | Type    | Constraint           |
|----------------|---------|----------------------|
| id             | UUID    | PK                   |
| floor_number   | INTEGER | NOT NULL             |
| active         | BOOLEAN | NOT NULL             |
| parking_lot_id | UUID    | FK → parking_lot(id) |

Unique constraint: `(parking_lot_id, floor_number)`

## 3. parking_spot

Stores individual parking spots.

| Column           | Type        | Constraint             |
|------------------|-------------|------------------------|
| id               | UUID        | PK                     |
| section          | VARCHAR(20) | NOT NULL               |
| spot_number      | VARCHAR(20) | NOT NULL               |
| spot_type        | VARCHAR(30) | NOT NULL               |
| active           | BOOLEAN     | NOT NULL               |
| parking_floor_id | UUID        | FK → parking_floor(id) |

`spot_type`: CAR, TWO_WHEELER

Unique constraint: `(parking_floor_id, section, spot_number)`

Note: `active` indicates whether the spot is operational, not whether it is occupied.

## 4. gate

Stores entry and exit gates.

| Column         | Type        | Constraint           |
|----------------|-------------|----------------------|
| id             | UUID        | PK                   |
| gate_number    | VARCHAR(20) | NOT NULL             |
| gate_type      | VARCHAR(20) | NOT NULL             |
| active         | BOOLEAN     | NOT NULL             |
| parking_lot_id | UUID        | FK → parking_lot(id) |

`gate_type`: ENTRY, EXIT

A parking lot can have multiple gates.

## 5. parking_ticket

Stores both active and historical parking sessions.

| Column              | Type        | Constraint            |
|---------------------|-------------|-----------------------|
| id                  | UUID        | PK                    |
| registration_number | VARCHAR(30) | NOT NULL              |
| vehicle_type        | VARCHAR(30) | NOT NULL              |
| parking_spot_id     | UUID        | FK → parking_spot(id) |
| entry_gate_id       | UUID        | FK → gate(id)         |
| exit_gate_id        | UUID        | FK → gate(id), NULL   |
| entry_time          | TIMESTAMP   | NOT NULL              |
| exit_time           | TIMESTAMP   | NULL                  |
| active              | BOOLEAN     | NOT NULL              |

Vehicle details are stored directly in the ticket table. There is no separate vehicle table.

`active` indicates whether the vehicle is currently parked.

### Important indexes

Prevent multiple active tickets for the same vehicle:

```sql
CREATE UNIQUE INDEX uk_active_vehicle
    ON parking_ticket (registration_number) WHERE active = TRUE;
```

Prevent multiple active tickets for the same spot:

```sql
CREATE UNIQUE INDEX uk_active_spot
    ON parking_ticket (parking_spot_id) WHERE active = TRUE;
```

Useful lookup index:

```sql
CREATE INDEX idx_ticket_active_spot
    ON parking_ticket (parking_spot_id) WHERE active = TRUE;
```

## 6. payment

Stores individual payment attempts.

| Column                | Type          | Constraint              |
|-----------------------|---------------|-------------------------|
| id                    | UUID          | PK                      |
| ticket_id             | UUID          | FK → parking_ticket(id) |
| amount                | NUMERIC(12,2) | NOT NULL                |
| payment_method        | VARCHAR(20)   | NOT NULL                |
| payment_status        | VARCHAR(20)   | NOT NULL                |
| transaction_reference | VARCHAR(100)  | NULL                    |
| created_at            | TIMESTAMP     | NOT NULL                |
| updated_at            | TIMESTAMP     | NOT NULL                |

`payment_method`: CASH, CARD, UPI

`payment_status`: PENDING, SUCCESS, FAILED

One ticket can have multiple payment attempts.

## Parking Spot Allocation – Database Concurrency

Use a single database transaction for spot reservation and ticket creation.

1. Find the least-occupied eligible floor.
2. Select an available spot using `FOR UPDATE SKIP LOCKED`.
3. Insert the parking ticket.
4. Commit the transaction.

If ticket insertion fails, the transaction rolls back and releases the spot lock.

The partial unique indexes provide additional protection against duplicate active tickets.

**Key principle:** `parking_ticket` is the source of truth for parking occupancy. A spot is occupied when an active
ticket references it.

# Parking Lot – SQL Queries (PostgreSQL)

These are the operational queries for vehicle entry, spot allocation, ticket creation, vehicle exit, and payment.

## 1. Check whether a vehicle is already parked

```sql
SELECT id
FROM parking_ticket
WHERE registration_number = :registrationNumber
  AND active = TRUE;
```

If a record exists, reject the entry request.

## 2. Validate entry gate

```sql
SELECT id, gate_number
FROM gate
WHERE id = :gateId
  AND gate_type = 'ENTRY'
  AND active = TRUE;
```

## 3. Find the least-occupied eligible floor

Example for CAR:

```sql
SELECT pf.id                                          AS floor_id,
       pf.floor_number,
       COUNT(ps.id)                                   AS total_spots,
       COUNT(pt.id)                                   AS occupied_spots,
       COUNT(pt.id) * 100.0 / NULLIF(COUNT(ps.id), 0) AS occupancy_percentage
FROM parking_floor pf
         JOIN parking_spot ps
              ON ps.parking_floor_id = pf.id
                  AND ps.active = TRUE
                  AND ps.spot_type = 'CAR'
         LEFT JOIN parking_ticket pt
                   ON pt.parking_spot_id = ps.id
                       AND pt.active = TRUE
WHERE pf.active = TRUE
GROUP BY pf.id, pf.floor_number
HAVING COUNT(ps.id) > COUNT(pt.id)
ORDER BY occupancy_percentage ASC, pf.floor_number ASC LIMIT 1;
```

This excludes floors with no available spots.

## 4. Find and lock an available parking spot

Execute inside the same transaction.

```sql
SELECT ps.id, ps.section, ps.spot_number
FROM parking_spot ps
WHERE ps.parking_floor_id = :floorId
  AND ps.spot_type = :vehicleType
  AND ps.active = TRUE
  AND NOT EXISTS (SELECT 1
                  FROM parking_ticket pt
                  WHERE pt.parking_spot_id = ps.id
                    AND pt.active = TRUE)
ORDER BY ps.section, ps.spot_number LIMIT 1
FOR
UPDATE OF ps SKIP LOCKED;
```

If no spot is returned, try the next eligible floor.

## 5. Create parking ticket

```sql
INSERT INTO parking_ticket (id,
                            registration_number,
                            vehicle_type,
                            parking_spot_id,
                            entry_gate_id,
                            entry_time,
                            active)
VALUES (:ticketId,
        :registrationNumber,
        :vehicleType,
        :spotId,
        :entryGateId,
        CURRENT_TIMESTAMP,
        TRUE) RETURNING *;
```

Commit the transaction after successful insertion.

# Vehicle Exit

## 6. Retrieve active ticket

```sql
SELECT *
FROM parking_ticket
WHERE id = :ticketId
  AND active = TRUE
    FOR UPDATE;
```

## 7. Validate exit gate

```sql
SELECT id
FROM gate
WHERE id = :exitGateId
  AND gate_type = 'EXIT'
  AND active = TRUE;
```

## 8. Close parking session

```sql
UPDATE parking_ticket
SET exit_gate_id = :exitGateId,
    exit_time    = CURRENT_TIMESTAMP,
    active       = FALSE
WHERE id = :ticketId
  AND active = TRUE;
```

This releases the spot logically because occupancy is derived from active tickets.

# Payment

## 9. Record payment attempt

```sql
INSERT INTO payment (id,
                     ticket_id,
                     amount,
                     payment_method,
                     payment_status,
                     transaction_reference,
                     created_at,
                     updated_at)
VALUES (:paymentId,
        :ticketId,
        :amount,
        :paymentMethod,
        'PENDING',
        :transactionReference,
        CURRENT_TIMESTAMP,
        CURRENT_TIMESTAMP);
```

## 10. Update payment status

```sql
UPDATE payment
SET payment_status = :paymentStatus,
    updated_at     = CURRENT_TIMESTAMP
WHERE id = :paymentId;
```

A failed attempt remains in the database. A retry creates another payment record.

# Reporting and Lookup Queries

## 11. Get current parking occupancy by floor

```sql
SELECT pf.floor_number,
       ps.spot_type,
       COUNT(ps.id)                AS total_spots,
       COUNT(pt.id)                AS occupied_spots,
       COUNT(ps.id) - COUNT(pt.id) AS available_spots
FROM parking_floor pf
         JOIN parking_spot ps
              ON ps.parking_floor_id = pf.id
                  AND ps.active = TRUE
         LEFT JOIN parking_ticket pt
                   ON pt.parking_spot_id = ps.id
                       AND pt.active = TRUE
WHERE pf.active = TRUE
GROUP BY pf.floor_number, ps.spot_type
ORDER BY pf.floor_number, ps.spot_type;
```

## 12. Get ticket details with payment history

```sql
SELECT pt.id AS ticket_id,
       pt.registration_number,
       pt.vehicle_type,
       pt.entry_time,
       pt.exit_time,
       pt.active,
       p.id  AS payment_id,
       p.amount,
       p.payment_method,
       p.payment_status
FROM parking_ticket pt
         LEFT JOIN payment p
                   ON p.ticket_id = pt.id
WHERE pt.id = :ticketId
ORDER BY p.created_at;
```

## 13. Find all active parking tickets

```sql
SELECT *
FROM parking_ticket
WHERE active = TRUE
ORDER BY entry_time;
```

## 14. Find historical parking sessions for a vehicle

```sql
SELECT *
FROM parking_ticket
WHERE registration_number = :registrationNumber
ORDER BY entry_time DESC;
```

## 15. Find outstanding payments

```sql
SELECT pt.id AS ticket_id,
       pt.registration_number,
       p.id  AS payment_id,
       p.amount,
       p.payment_status
FROM parking_ticket pt
         JOIN payment p
              ON p.ticket_id = pt.id
WHERE pt.active = FALSE
  AND p.payment_status IN ('PENDING', 'FAILED')
ORDER BY p.created_at;
```

## Transaction boundaries

| Operation       | Transaction                                                            |
|-----------------|------------------------------------------------------------------------|
| Vehicle entry   | Check active vehicle → Find floor → Lock spot → Insert ticket → Commit |
| Vehicle exit    | Lock ticket → Validate exit gate → Close ticket → Commit               |
| Payment attempt | Insert payment → Update payment result                                 |

**Important concurrency guarantees:**

1. `FOR UPDATE SKIP LOCKED` prevents concurrent transactions from selecting the same locked spot.
2. Unique partial index on active `parking_spot_id` prevents duplicate active spot allocation.
3. Unique partial index on active `registration_number` prevents duplicate active vehicle tickets.
4. Database transactions ensure rollback if ticket creation fails.

**One important implementation detail:** The payment gateway call should not be made while holding the parking-ticket
database transaction open. Close the parking session first, then process payment separately.
